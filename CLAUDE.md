# boomi-connectordev

Notes for developers working on this skill.

## Layout

- `SKILL.md` is the entry point and navigation hub — scripts inventory, terminology, workflow, and one-hop routing to every reference file.
- `scripts/connectordev-common.sh` is the sourced library (env loading, URL builder, curl wrapper); never executed directly.
- `scripts/connectordev-*.sh` are per-noun CLI tools: `env-check`, `group` (incl. classifications), `version` (incl. the API's descriptor validation), `version-change`. `doctor`, `init` and `descriptor-lint` call no API and read no `.env`.
- `references/` holds the connector build/test knowledge; every file is routed from SKILL.md with a "Use when" line.
- `templates/connector-project/` is a working Gradle project that `scripts/connectordev-init.sh` copies and renames. It is a third skill subdirectory beyond the usual `references/` and `scripts/`. The alternative was a script emitting the same files as heredocs, which cannot be built and verified in place. Keep it buildable: change it only alongside a run of init plus `./gw connectorArchive`.
- References stay thin deliberately — stable contracts and traps live in `references/`; everything else is fetched live via SKILL.md's "Platform docs on demand" pattern. Don't bake in doc-page content that drifts.

## Conventions

- Credentials reach curl as a config file on stdin (`curl_cfg ... | curl -K -`) and `.env` values are read in-shell without export — never put a credential in argv, a child environment, or an `Authorization` header built by hand.
- `.env` is parsed, not sourced: `load_env` reads only the keys in `_ENV_KEYS` and ignores every other line, so nothing in the file executes, no value is expanded, and a `PATH` or `BASH_ENV` line — or a sibling skill's keys in a shared `.env` — is inert. A value counts as literal when single-quoted, double-quoted carrying no `$` or `\`, or bare and drawn only from `A-Za-z0-9._:/@+=-`; anything else is refused by line number, never by printing the line. Parsing blocks code execution, not a hostile value: a crafted `.env` can still set a key the scripts trust, which is why `BOOMI_ACCOUNT_ID` and `BOOMI_API_URL` are checked after the load rather than trusted from it.
- Because auth occupies stdin, scripts must never pipe data into `connectordev_api` or use `@-` / `-T -`; inline `-d` and `--data-binary @file` are fine, subject to the `@` rule below.
- A caller-supplied value sent as a request body goes out under `--data-raw`. `-d`, `--data`, `--data-ascii` and `--data-binary` all read a leading `@` as a file reference and send that file's contents in place of the value; `--data-raw` alone does not, and is otherwise identical for an inline value. `--data-binary @file` stays correct where the `@` is the script's own, naming a file the caller asked for.
- `-F "name=value"` must not carry free text: `-F` reads `;` as a parameter separator and a leading `@` or `<` as a file reference, so text containing them is silently truncated, and a value that happens to name an existing file uploads that file's contents. Use `--form-string` for a plain identifier, or `-F "name=<file;type=text/plain; charset=UTF-8"` when the text needs a declared charset — a part with no declared charset leaves the decoding to the receiver, and `--form-string` cannot declare one.
- Free text sent to this API is echoed back in the response, and a 2xx says nothing about what was stored: a value altered anywhere on the client encoding path is stored, and echoed, in its altered form. A script sending free text compares the echoed value against what it sent and reports a mismatch. Where a response escapes non-ASCII as `\uXXXX` and the sent text carries some, a substring comparison cannot match it, so that case is reported as unverifiable; a plain-ASCII value stays comparable, and a miss there is reported as a mismatch.
- A value interpolated into a hand-built JSON body goes through `json_escape`. It covers the named JSON escapes except `\uXXXX` and refuses a control character it cannot represent; it does not validate UTF-8. A caller that must not refuse — a multipart part where the character is legal, or a comparison drawn after a request has already succeeded — uses `json_escape_chars`, the same substitutions without the refusal.
- Every guarded function declares `local _XTRACE_WAS_ON` before calling `xtrace_off`. Bash scopes `local` dynamically, so `xtrace_off`'s assignment binds to the calling function's local rather than the global, and each invocation keeps its own saved state. Without it a guarded function calling another overwrites the outer's saved value — the inner reads tracing as already off, records 0, and the outer's restore silently drops tracing for the rest of the run. Add the declaration to any new guarded helper.
- `curl_cfg` guards its own body, but a guard inside a function cannot cover what the caller does on either side of the call: the shell expands the arguments before the function runs, and a caller capturing the output records it after `xtrace_restore`. So a new caller guards before it expands a credential into the call, and captures only a value that does not carry one — `connectordev_api` keeps the config text inside the pipeline and captures the HTTP code alone.
- A user value interpolated into a URL path goes through `require_path_segment` at the call site, not inside `connectordev_url` — that function receives its endpoint's own constant slashes and cannot tell them from an injected one. curl normalises the path before sending, so an unchecked separator reaches a different endpoint than the subcommand names.
- A caller-supplied path interpolated as curl's `@path` goes through `require_local_file`, which subsumes the existence check. It refuses the names curl reads as stdin — `-`, `/dev/stdin`, `/dev/fd/N` — since stdin carries the auth config and the request would go out with an empty body; a symlink to one of those is not caught. It also refuses `;` and `,`, which the `-F` rule above makes separators: the truncation target is a file the caller did not name, and only sometimes does not exist, in which case curl fails loudly instead. Both are inert for `--data-binary`, and refused there too.

## API surface

Scripts call the Connector Deployment API (`{BOOMI_API_URL}/connector/api/rest/v1/{accountId}`): ConnectorGroup, ConnectorClassification, ConnectorVersion, ConnectorVersionChange, ConnectorDescriptorValidation, and both query resources. The Connector Management API resources (review, visibility, metadata, icon, pending release) are not covered.
